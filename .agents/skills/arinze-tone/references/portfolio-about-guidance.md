# Portfolio and About guidance for Arinze

Use this when writing portfolio copy, LinkedIn About sections, personal summaries, or project positioning for Arinze.

## Core positioning

Position Arinze as a full stack software engineer, backend-focused, building business systems, automation pipelines, and AI workflow tools.

Do not reduce him to:

- Python programmer only.
- Backend-only engineer.
- Haxaml-only builder.
- AI enthusiast.

The About should show multiple proof points across experience: Vigilis, Pharmax, internal tooling, HaxJobs, Haxaml, FRAME/agent workflow work where relevant.

## About section structure

A strong About should normally include:

1. One clear positioning paragraph.
2. One stack/workflow paragraph.
3. A compact accomplishments list.
4. A short paragraph connecting the work pattern.
5. A current direction paragraph.

The accomplishments list should be concrete and cross-experience, for example:

- Full pharmacy operations system as sole developer.
- Full SaaS product with frontend, backend, and AI integration.
- Internal tooling across admin workflows, backend logic, and data handling.
- HaxJobs automated job-search workflow.
- Haxaml Git-style engine for AI agent workflows.

## Writing rules from user corrections

Avoid these patterns:

- Generic value-claim lines that could fit almost any engineer.
- "This is not X, but Y" contrast templates.
- Softer variants like "not demos that..., but systems that...".
- Haxaml-only identity.
- Repeated FRAME explanations.
- Long FRAME breakdowns unless the user asks for a technical explainer.
- LinkedIn influencer rhythm, especially one sentence per line.
- Broad market commentary taking over the About.
- Unnecessary standalone links at the end when the user wants compact copy.
- Excess whitespace between every sentence.

Prefer:

- Normal paragraphs.
- Compact but substantive structure.
- Specific systems and workflows.
- Accomplishments across experiences.
- Clear stack mentions.
- One compact Haxaml mention.
- Human, direct wording with normal punctuation.

## Character-limited About drafting

When the user requests a maximum character count, write the draft directly under the limit and verify mentally or with tools if available.

For 2,600-character About sections:

- Remove standalone GitHub/Haxaml links unless explicitly requested.
- Remove excessive whitespace.
- Keep one blank line between paragraphs or list blocks only.
- Cut repeated project explanations.
- Prefer one compact accomplishment list over long prose.
- Keep Haxaml explanation to one or two sentences.

## Portfolio concept guidance

A strong portfolio for Arinze should be proof-led and interactive, not just a static CV website.

Useful sections:

- Home: positioning, proof cards, selected work.
- Work: Vigilis, Pharmax, HaxJobs, Haxaml, and other serious projects.
- Lab: experiments, prototypes, agent workflow work.
- Writing: short engineering notes that show how he thinks.
- About: human story plus proof.
- Contact: email, GitHub, LinkedIn, CV.

Useful interaction ideas:

- Audience switcher: Recruiter, Developer, Founder / small business, AI tooling nerd.
- Project proof cards.
- Live proof console with GitHub activity, test/build status, demo pipeline output, and timestamps.
- Haxaml context preview.
- HaxJobs application-pack preview.
- Inventory workflow simulator inspired by pharmacy operations.
- Architecture maps per serious project.
- "Ugly constraints" boxes on project pages.
