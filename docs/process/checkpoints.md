# Checkpoints: every 10 plans

A standing ritual, not a numbered plan. After every 10 plans — after
plan 010 before 011, after 020 before 021, and so on until the product
is fully built — do this before moving to the next plan:

1. **Walkthrough** of the last 10 plans: verify each plan's state,
   owner decision, deliverables, and the green test floor. Record gaps.
2. **Knowledge update**: go online and update how we do things and how
   we code. Record sources and what changes in this repo.
3. **Codify**: fold what changed into the standing docs in this
   directory (subagent-fleet.md, tdd-workflow.md), written
   harness-agnostic — roles and discipline first, harness bindings in
   an appendix.
4. **Prove it**: run one real slice through the updated workflow with
   the red phase recorded.
5. Record the checkpoint in the dated file below.
