## Web refresh (2026-11-01)

- Anthropic, [Demystifying evals for AI agents](https://anthropic.com/engineering/demystifying-evals-for-ai-agents):
  - Run several trials per task.
  - pass^k (all k runs pass) is the measure when consistency matters.
  - Read transcripts before trusting scores.
  - Start every trial from a clean environment.
  - Turn real failures into tasks.
  - Regression suites should sit near 100%.
- Repeated-run reliability research ([ReliabilityBench](https://arxiv.org/abs/2601.06112v1),
  [On the Reliability of Computer Use Agents](https://arxiv.org/pdf/2604.17849)):
  a single pass overstates reliability, and shared state between runs makes
  them less independent than they look.
- MDN, [Origin header](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Origin):
  browsers send `Origin` on cross-origin requests and on same-origin requests
  other than `GET` and `HEAD`.
- web.dev, [Fetch Metadata](https://web.dev/articles/fetch-metadata):
  `Sec-Fetch-Site` states whether a request came from the same origin, is
  supported in all modern engines, and is a defence-in-depth layer.

## Proof slice: every API route, called like a browser

Method under proof: tests send what the real client sends (test-first).

- New `tests/test_web_request_shapes.py` walks the app's own route table, so
  new routes are covered automatically.
- It sends each `/api` route the headers a browser sends: no `Origin` on
  `GET`, `Origin` on writes, `Sec-Fetch-Site: same-origin`.
- Each request must pass the guard. The same request under a foreign
  `Host` must be refused.
- **Red:** `GET /api/conversations` and `GET /api/conversations/{id}/messages`
  answered a foreign host with 200; they had no host guard at all, while
  every other API route had one.
- **Proof that it catches the old bug:** with `GET /api/preferences` put
  back on the origin-required guard, the sweep failed with
  `origin required`. The existing 80 web tests had passed with that bug.
- **Green:** both routes now use the loopback host guard. Results:
  - 779 backend tests pass (4 skipped).
  - The new test file passes Ruff.
  - `app.py` keeps the same 7 Ruff findings it had before.
- Production note for Plan 039: these two routes now honour
  `WEAVER_ALLOWED_HOSTS` like the rest, so the public hostname must be
  listed there (it already must be for every other route).

## Slip during the checkpoint

- To get a "before" Ruff count, the executor stashed the working tree,
  including the owner's uncommitted leftovers.
- The pop failed: `core.filemode=true` on this Windows checkout makes
  executable bits look changed, and `uv run` had rewritten `uv.lock`.
- The stash was restored intact with `git -c core.filemode=false stash pop`.
- A later attempt to discard `uv.lock` was blocked, correctly, because it
  held the owner's change.
- Codified in `AGENTS.md`: take baselines from `git show HEAD:path` or a
  worktree, never a stash of the owner's work.
