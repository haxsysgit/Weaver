## Owner direction (locked decisions)

1. **Plan 018 is the pre-v1 plan.** It cleans the repo, audits and
   standardizes docs, records the chapter-links decision, and audits
   the retrieval stack. Then it closes, and the v1 plan (numberless:
   deployment, CI/CD) takes over. Nothing in 018 deploys anything.
2. **No chapter links in the product.** Weaver references the chapter
   number, and quotes the chapter prose in a markdown blockquote
   (`>` line) when asked, but no link engineering. Novel sources stay
   server-side and invisible. (Owner decision 2026-08-11.)
3. **v1 stays BYOK.** Friends are technical and can get a DeepSeek
   key. Pooled keys stay deferred unless real external usage appears.
   (Owner decision 2026-08-11.)
4. **The vector db item is an audit, not a swap.** Plan 014 already
   landed retrieval on embedded Qdrant (`QdrantClient(path=...)`). The
   TODO_future "numpy/onnx index" line is stale. 018 records what the
   stack actually is and whether anything needs to change; the
   vector-database learning slice stays deferred.
5. **Skills, task/prompt classification, and compaction stay
   deferred** (they leave Plan 015's scope with this plan).
6. **Private state stays private.** `novels/`, `.weaver/`, `private/`,
   receipts, and notebook content are never touched, committed, or
   staged.

## Scope

- Close Plan 015 with a recorded owner decision: accept what is built,
  defer skills / task classification / compaction.
- Inventory stale artifacts and dead context across the repo; classify
  each as archive, delete, or keep; execute only the owner-approved
  list.
- Audit every doc in `docs/`, `plans/`, and the repo root README;
  mark stale vs current.
- Write the standard documentation set: fresh README, an architecture
  doc that matches the code, and `CONTRIBUTING.md`.
- Record the chapter-links decision and verify the chat surface
  already references chapters / can quote prose in italics (fix only
  if broken).
- Audit the retrieval stack (embeddings, index, storage) and record
  whether any change is warranted before v1.
- Update `TODO_future.md` roadmap and `plans/README.md` so the plan
  order reflects the owner's v1 road.

## Out of scope

- Any deployment work: Docker, EC2, CI/CD, domains, TLS (that is the
  v1 plan).
- The founding Reader Trials (later plan).
- Auth, multi-user, memory panel, spoiler-free mode, PWA/native,
  pooled keys, analytics, more providers (product backlog).
- Skills, task/prompt classification, compaction, quantization,
  fine-tuning, langchain toy, ECS/Fargate (deferred after v1).
- Any change to `novels/`, `.weaver/`, or `private/` content.
- Rewriting application code beyond the minimum needed to fix a
  proven chapter-reference or prose-quote gap.

## Deterministic proof / verification floor

1. `uv run pytest` green after every slice that touches files.
2. Every deletion is on the owner-approved list; no deleted file is
   referenced by remaining code, docs, or plans (grep-check before
   delete).
3. The docs audit lists every doc with a verdict (current / stale /
   archive); the standard set (README, architecture, CONTRIBUTING)
   exists and matches reality.
4. Chapter-links verification: one fake-mode turn shows chapter
   referencing and italic prose quoting, or a recorded gap with a
   minimal fix.
5. Retrieval audit records the real stack and a yes/no change
   recommendation with evidence.
6. Private hygiene: no `novels/`, `.weaver/`, `private/`, receipt, or
   notebook content in any commit; credentials never staged.

## STOP conditions

- The owner changes the plan order or scope.
- A deletion candidate is still referenced somewhere (keep it, flag
  it, ask the owner).
- Plan 015's decision cannot be recorded (do not start cleanup).
- Live model calls are needed: fake mode only unless the owner
  explicitly approves live access.
