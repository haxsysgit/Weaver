# Plan 027.5: v1.2.1 mobile thread hotfix

> **Executor instructions:** Repair the released mobile New Weave and thread
> recall regressions at their shared startup boundary. Show the existing
> Spellweave first, then reveal the current approved interface only after the
> conversation state is ready.

## Status

- **Tooling:** root Vitest and Vite commands, `uv run pytest`, fake web mode,
  mobile browser evidence, and the existing GitHub Actions deployment.
- **State:** admitted 2026-08-31 by owner direction.
- **Depends on:** Plan 027 closed and Weaver 1.2.0 released.
- **Priority:** P0. New conversation and conversation recall are core mobile
  navigation paths in the live release.
- **Effort:** S to M after the installed-app repair was added.
- **Risk:** Medium. The repair touches asynchronous startup, active
  conversation identity, mobile drawer closure, and first paint order.
- **Budget:** about 8k to 18k agent-context tokens, estimated $0.10 to $0.60.
  Product verification is fake-only with $0 provider spend.

## Owner direction (locked decisions)

1. (2026-08-31, amended after red proof) New Weave keeps an already empty
   thread, closes the mobile Archive, confirms the tap through the existing
   rune feedback, and focuses the composer. From a used thread it creates and
   selects a distinct server-backed conversation.
2. (2026-08-31) Tapping an older mobile thread must load that transcript before
   the Archive closes. A failed or blocked recall stays visible and tells the
   reader what happened.
3. (2026-08-31) The existing approved Spellweave is the first visible app
   surface. Soul Sea, Archive, transcript, controls, and composer follow after
   conversation startup completes.
4. (2026-08-31) Preserve the approved transparent messages, Soul Sea art,
   settings, Thread Archive layout, First Nightmare rite, and motion language.
5. (2026-09-01) The Chrome install prompt is the supported Weaver PWA. Its
   standalone window must keep the void continuous around Android system UI,
   open Settings immediately, and pause hidden visual work while Settings is
   active. Preserve the approved Soul Sea and Spellweave composition.

## Scope

- Add an explicit conversation-startup state to the shared chat controller.
- Prevent startup completion from overwriting a newer thread selection.
- Make idle New Weave truthful: reuse an already empty thread, or create and
  select a distinct server-backed conversation when the current thread is used.
- Close the mobile Archive only after recall succeeds; keep it open with safe
  feedback when recall fails or a turn blocks it.
- Paint the current Spellweave first and reveal the approved interface after
  startup, with an immediate reduced-motion state.
- Add focused regressions for slow startup, mobile recall, failed recall, New
  Weave, and first-paint order.
- Repair the installed PWA boundary: match the standalone system-bar color,
  open Settings before the preference request settles, and pause hidden or
  decorative Soul Sea motion while the full-screen settings surface is open.
- If accepted, release as Weaver 1.2.1 through the existing main-branch deploy.

## Out of scope

- Any redesign of the Conversation Chamber, Archive, settings, Soul Seas,
  First Nightmare, or approved icon set.
- Provider, retrieval, prompt, notebook, private library, key, persistence
  schema, AWS infrastructure, or deployment-workflow changes.
- Live model calls or private chapter reads.

## Deterministic proof / verification floor

1. Focused Vitest regressions prove New Weave empty/used behavior, delayed
   startup recall, failed recall, drawer truth, focus, and Spellweave-first
   rendering.
2. `npm run build` passes and refreshes committed `src/weaver/web/dist/`.
3. `npm test` passes in full.
4. `uv run pytest` passes in full before release.
5. Fake-mode evidence covers a phone viewport recalling an older thread and
   starting a new weave after reload.
6. Installed-mode evidence covers full-window background continuity and an
   immediately responsive Settings open at a phone viewport.
7. `git diff --check` passes and staged files contain no credentials, private
   source text, chats, or unrelated worktree drift.

## STOP conditions

- If the defect requires a persistence schema change, private source access,
  provider traffic, or AWS infrastructure work, stop and return to the owner.
- If Spellweave-first loading delays usable controls beyond the real startup
  request or can leave the app permanently hidden, stop and simplify it.
- If the repair changes any accepted visual composition beyond reveal timing,
  stop and show the owner before release.
- Stop after verified implementation for the owner's accept or reject decision.
  Deploy only after acceptance.
