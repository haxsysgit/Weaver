## Scope

- Stabilize `weaver refresh` (corpus/service.py update path):
  bounded retries with backoff on transient errors (timeout/429/
  provider), stop only on NOT_FOUND or hard errors (auth/config),
  `--through` cap already exists — keep it, add last-chapter reporting,
  pin idempotent-resume behavior with tests.
- **Slice 2.5: direct HTTP source (self-served refresh).** New
  `DirectHttpChapterSource` implementing the same `ChapterSource`
  protocol: httpx (already a transitive dep) with browser headers, no firecrawl, $0.
  CLI `--source direct|firecrawl` flag; direct becomes the default
  only if a live batch through the real chapters survives Cloudflare
  (per owner approval 2026-08-15). Firecrawl stays as the fallback.
- Live refresh run to bring the shelf from 3,148 to the real last
  chapter (probe until first 404; expected ~3,160 per owner).
- Recover from git history: `scripts/colab_index.py`, the colab sweep
  notebook, `questions-colab.json` / the labeled question sets, and the
  sweep reports (`colab-sweep-bge-40wins.md`, etc.) — into
  `scripts/` or `.weaver/research/` as history, NOT into the live index
  path.
- Fix the ceiling bug: `DEFAULT_CEILING = 1000` in
  scripts/build_library_index.py → derive the ceiling from the shelf
  (novels manifest / urls.md last_chapter), so re-embedding covers the
  whole novel, not 1-1000.
- Re-embed the whole novel (3,160 chapters) locally with bge-large,
  rebuild the index at .weaver/retrieval/index.
- Re-run the question sweep locally against the new index; compare
  hit@5/MRR to the recovered colab numbers; write the
  before-quantization baseline.
- 50-question eval set (drawn from different arcs) + run real weaver
  against it + owner grades (the owner's requested flow, folded in).

## Deterministic proof / verification floor

1. `uv run pytest tests/test_corpus_fetch_update.py tests/test_corpus_source.py -q`
   green after the retry/stop-semantics changes (new tests included).
2. `uv run pytest -q` full suite green before any commit that touches
   src/.
3. Fake-mode refresh test proves: transient error → retries →
   succeeds; persistent transient → stops with error, no partial
   corruption; NOT_FOUND → first_404 stop; resume works (rerun skips
   already-saved chapters).
4. Recovered colab artifacts listed in results.md with source commits.
5. Re-embed completes with no errors; index point count > old count
   (was 6,826 novel_chunks for ceiling 1000); chapter coverage verified
   (last indexed chapter == shelf last chapter).
6. Sweep re-run numbers recorded next to the old colab numbers in
   results.md; any gap explained (different chunking, machine, model
   version), not hidden.

## STOP conditions

- Live refresh shows the source behaving erratically (repeated
  provider/429 past retries) → stop, show the receipts, ask owner.
- Re-embed CPU time exceeds sane bounds (hours) → stop and propose
  chunked/backgrounded run.
- Recovered sweep numbers unreproducible within reason → stop, show
  both datasets, ask owner before proceeding.
- Any private content (novels/, .weaver receipts) at risk of landing in
  git/committed files → stop immediately.
